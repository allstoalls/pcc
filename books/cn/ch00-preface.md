# 前言

## 本书导读:全书的三个层次

全书按三个层次组织:第一层讲 pcc 为什么存在,第二层讲 C/Python/运行时怎样拼成一条执行链,第三层讲哪些证据能证明这些声明没有越界。

- 第 1-4 章先建立共同语言:什么叫"拥有执行",以及 C 前端怎样把真实 C 代码降到 LLVM IR。
- 第 5-15 章进入主干系统:Python 前端、对象模型、异常、引用、GC、后端、no-libpython 与自举不动点。
- 第 16-18 章收束到长期路线:值模型、包生态/C-API,以及如何用测试和调查保持声明诚实。

## 这是一本什么书

这是一本以**一个真实的、正在演化的系统**为对象的设计与实现之书。它的传统可以
追溯到 Lions 对 UNIX 第六版源代码的注释,和 McKusick 等人的
《The Design and Implementation of the 4.4BSD Operating System》:不是用玩具
示例讲授一般原理,而是把一个完整系统摊开,逐层回答三个问题——**为什么是这个
设计,它是怎么实现的,以及它在真实世界里是怎么坏过的。**

本书的对象是 pcc:一个用 Python 写成的编译器工具链。它在一个仓库里装着两个
编译器和一个运行时——

1. 一个成熟的 **C 前端**,把 C 语义低层化(lowering)到 LLVM IR,能编译并运行
   Lua、SQLite、PostgreSQL `libpq`、zlib、OpenSSL、nginx 这样的真实项目;
2. 一个实验性的**类型化 Python 前端**,支撑自托管(self-hosting)路线;
3. 一个带**五个可插拔 GC 后端**的原生运行时,以及一条不依赖 LLVM 的
   self 后端原生发射路径。

pcc 的论题不是"让 Python 变快",而是让 Python 的执行**可被拥有**:可编译、
可审计、可自举、可感知包生态、对每一条回退(fallback)边界诚实。性能被视为
已证明语义的后果,而不是弱化 Python 行为的执照。这个立场贯穿全书,也贯穿
仓库里每一条工程规则。

## 这本书不是什么

本书不是 pcc 的用户手册,也不是编译原理教科书。读者应当已经知道什么是 AST、
SSA、引用计数和三色标记;本书不再从头定义它们,而是讲它们在一个必须同时满足
"CPython 语义、no-libpython 链接、五 GC 平等、字节级自举不动点"的系统里如何
互相挤压、互相成全。

本书也继承 pcc 的**声明卫生**(claim hygiene):书中每一条能力声明都标注模式
——host pcc 与 pcc1 不同,libpython 与 no-libpython 不同,LLVM 后端与 self
后端不同,stage1 通过与 pcc1→pcc2→pcc3 不动点不同。凡是实验性的,书里就写
实验性;凡是已确认的缺陷,书里就如实记录,修复后补记结局(第 16 章 typed-int
溢出缺陷从确认到修复的全程档案是范例)。一本对自己的系统撒谎的书不配谈设计。

## 读者假设

- 会读 Python 和 C,能看懂少量 LLVM IR 与 AArch64 汇编片段;
- 了解编译器的基本分期(解析、类型、IR、代码生成)与 GC 的基本词汇;
- 最好手边有 pcc 仓库源码——本书所有引用都指向真实文件与真实标识符,
  本书就是为"对照源码阅读"而写的。

## 本书的写法

每章遵循同一结构:先是**问题与设计空间**(为什么需要这个子系统,备选设计是
什么,为什么放弃),然后是**机制**(落在真实源文件、真实函数名上的实现),
然后是**历史与教训**——取材于仓库 [docs/investigations/](../../docs/investigations) 目录下两百余篇真实
调查记录的"案例研究":症状、错误假设、证据链、根因、留下的不变式。最后是
练习,从"读源码验证一条断言"到"论证一个设计权衡"分层。

案例研究是本书的一等内容,不是花絮。一个系统真正的设计约束,往往只有在它
被违反、把自举呈现红色状态、把 GC 触发崩溃之后才显形。[docs/investigations/](../../docs/investigations) 是这个系统
的化石层,本书大量引用它们的文件名与日期,读者可以回到原始记录核对每一句话。

## 如何读

全书九部十八章。三条阅读路径:

- **编译器路径**:第 1–6 章(总览、C 前端、Python 前端)→ 第 12–13 章
  (LLVM 与 self 后端)→ 第 15 章(自举不动点)。
- **运行时与 GC 路径**:第 1–2 章 → 第 7–9 章(对象模型、异常、所有权)→
  第 10–11 章(五 GC)→ 第 14 章(no-libpython)→ 第 16 章(值模型)。
- **方法论路径**:第 1 章 → 第 15 章 → 第 18 章。若只想知道"一个多智能体
  时代的系统仓库如何不骗自己",读这三章。

## 版本与体例

本书对应 2026 年 6 月的 pcc 仓库状态(0.1.3 之后、五 GC 自举闸已全部通过的主线)。
代码会继续演化,因此本书引用源码一律用**文件路径加标识符名**
(如 [pcc/runtime/src/py_gc_backend.c](../../pcc/runtime/src/py_gc_backend.c) 中的 `pcc_gc_store_ptr()`),
不用行号。当书与代码冲突时,以代码为准——这也正是本书想教的阅读习惯。

代码标识符、CLI 旗标、环境变量(`PCC_GC_BACKEND`、`--python-libpython=off`)
保持英文原样。固定译法见附录 B 术语对照表。
