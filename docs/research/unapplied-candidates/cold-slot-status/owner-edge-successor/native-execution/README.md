# Cold slot-status callsite: bounded native execution

This packet proposes native execution of the two already compiled, hash-bound Linux x86-64 callsite executables. It does not compile or change the preserved program. Both binaries use the same candidate compiler and 191-member, threaded, atomic-refcount owned runtime. The reference replaces only the outlined reporting method with its former inline implementation; it is not an independent baseline compiler/runtime.

At creation all four executions are UNRUN. Run candidate GC0, candidate GC1, inline-reference GC0 and inline-reference GC1 serially, once each, only after separate supervisor admission. Preserve any failure and stop for diagnosis rather than changing the program, compiler or limits.

The caller must provide a separately reviewed exclusive-lock supervisor which owns the launched process through a pidfd. Its outer bound is 15 seconds, including cleanup reserve; the native program has a 10-second default SIGALRM, explicitly unblocked before exec. A pinned isolated Python interpreter performs identity checks, irreversibly sets 4 GiB address-space and zero-process limits, then replaces itself with the already-open verified static ELF descriptor. It creates no subprocess. The supervisor keeps direct durable stdout/stderr and records root reaping and ECHILD. The existing compiler bootstrap's execution denial is unchanged.

The launcher checks an unprivileged identity, zero capabilities, existing NoNewPrivs, live supervisor state, exact compiler/runtime/program provenance, regular executable mode, ELF bytes and the absence of a dynamic interpreter. It supplies a minimal environment with an empty PATH and explicit JSON GC logs. These resource limits are not a filesystem/network sandbox. The executable is trusted project code; no general untrusted-native execution is proposed.

The outcome validator requires successful exit, exactly `slot-status-owned-callsite-ok\n`, empty stderr, the requested collector observed in actual collection events, unchanged ELF bytes and complete supervisor cleanup. It uses the same JSON category/event/value1 collector predicate as the preserved native fixture. The production runtime was built with threads enabled; zero-process execution limits are suitable only for this GC0/GC1 gate. GC2–4 remain unqualified because collectors may need worker threads.

This program covers the original ValueError identity/message, TypeError argument binding, an owned temporary's finalization and the three generated callsite status/cleanup edges. It does not cover the separate C fixture's fresh RuntimeError creation and source-frame comparison, compiled pcc1, macOS execution, full async/gateway suites or all five collectors. A passing result must retain these limits.

Invoke `launch_elf.py` through the admitted supervisor using `--manifest`, `--manifest-sha256`, `--compile-output`, `--arm`, `--gc` and a fresh `--output` directory. The output must be a sibling of that invocation's fresh supervisor output. After terminal cleanup, invoke `validate_native.py` with the same arguments and `--guard-output`. All artifact identities are in `manifest.json`; it has no workspace-specific paths. Independent source review and execution admission are recorded separately from this frozen creation state.
