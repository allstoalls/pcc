# pcc Binary Symbol Naming

Status: D0 skeleton for the `pcc disassemble` plan. This file documents
symbol families that already exist and marks the parts that still need to be
made contractual before any binary-only decompiler claim.

This is not a disassembler implementation. It is the ABI note that future
Tier B work must parse instead of reverse-engineering ad hoc names from
generated binaries.

## Current Families

### User Functions

Pattern:

```text
_user_pcc_<module>_<function>
```

Meaning: lowered Python function body owned by `<module>`.

D0 status: observed in generated code paths; escaping rules for module and
function names still need a dedicated fixture matrix before this is a stable
ABI.

### Classes

Pattern:

```text
.class.<module>.<class>
```

Meaning: global class object for a pcc-native Python class.

D0 status: generated by `pcc/frontends/python/codegen/class_gen.py`. Future changes
to class global naming must update this spec and the disassemble corpus.

### Function Objects

Pattern:

```text
.func.<module>.<function>
```

Meaning: runtime function object global associated with a Python callable.

D0 status: used as a recognized symbol family by the disassemble plan; exact
coverage and escaping rules still need fixtures.

### String Literals

Pattern:

```text
.str.<hash-or-id>
```

Meaning: compiler-generated string literal global.

D0 status: stable enough for source-map/debug lookup planning, not yet enough
for binary-only source reconstruction. Tier B must treat string content as
recoverable only when the binary data and sourcemap constraints agree.

## Contract Rules

- Generated symbol names are a compiler/debug ABI for disassemble tiers C and
  B.
- Any codegen change that renames one of these families must update this file
  and the corresponding round-trip/disassemble corpus report.
- Tier B output must fail visibly with `# unrecovered: <reason>` when a symbol
  does not match this spec.
- This spec does not authorize source embedding in binaries.

## Open D1/D2 Work

- Add fixture binaries for each family on macOS arm64 and Linux x86_64.
- Define escaping for dots, underscores, nested functions, lambdas, and class
  methods.
- Record whether each symbol is required in stripped and unstripped binaries.
- Connect this spec to `docs/reports/disassemble-corpus.md` once the first
  round-trip gate exists.
